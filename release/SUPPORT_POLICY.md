## 1. Supported configuration

The release target is Windows 10/11 using the included local launcher and the
browser versions listed in release/release-policy.json. macOS and Linux use
run_local.sh and require Python 3. Commercial support is not approved until
signed 30-minute Chrome, Edge, Firefox, and integrated-GPU sessions pass the
release audit.

Opening index.html directly is unsupported because browsers restrict local
JavaScript modules and assets.

## 2. What support covers

Support is intended to cover installation and launch failures, reproducible
gameplay defects, save import/export, accessibility settings, controller
mapping, audio unlock, and corrupted packaged files. Support does not promise
compatibility with modified builds, unsupported browser extensions, altered
assets, unofficial mirrors, or devices below the approved matrix.

## 3. Reporting a defect

A useful report should include product version, operating system, browser and
version, GPU and driver, input device, display resolution, performance tier,
exact reproduction steps, expected and observed result, and a screenshot when
safe. Users must remove personal or sensitive information before attaching
files. Save exports should be shared only when requested through an approved
private support channel.

## 5. Save backup and recovery

Use the in-game save export control to download a JSON backup before browser
cleanup, updates, or migration. Import validates the save envelope and
checksum. Each slot maintains a local recovery backup, and reset may retain a
local archive. These mechanisms reduce risk but are not cloud backup.

## 6. Accessibility support

The current build includes remappable keyboard controls, gamepad deadzone and
sensitivity, vibration control, audio mixer settings, effect captions,
reduced-effects mode, and high-contrast HUD. Reports should identify the
setting and the blocked task. The final policy must name an accessibility
contact and response process.

## 8. Refunds and storefront escalation

Refund requests must follow applicable consumer law and the policy of the
storefront that processed payment. The final version must list every approved
storefront, its refund route, regional cooling-off disclosures, exceptions,
and publisher escalation contact. Support must not promise a refund that the
publisher or storefront has not approved.

## 9. Security reports

Potential vulnerabilities should follow SECURITY.md. Do not include
credentials, private keys, or sensitive personal data in public issues.

## 10. Policy changes

The final policy must state how material changes are announced, whether an
older supported build remains available, and which terms apply to an existing
purchase. Publisher, storefront, and consumer-law commitments must remain
consistent across this policy, the EULA, privacy notice, and store page.
